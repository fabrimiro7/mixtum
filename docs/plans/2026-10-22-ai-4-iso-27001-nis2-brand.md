# AI 4 ISO 27001 & NIS2 — visible brand

## Goal and non-goals

Show `AI 4 ISO 27001 & NIS2` across the Console, Public Frontend, Keycloak login and new TOTP enrollments in every generated instance. Keep realm ID, OIDC clients, audience, package names, paths and `mixtum` runtime keys unchanged.

## Current state and target architecture

Both Angular shells contain hard-coded `Mixtum` text and an invalid favicon URL. The canonical Keycloak realm and its existing-realm reconciler use `Mixtum` as display name; the login theme wordmark also contains it. Update presentation assets in their existing owners. The Keycloak realm display name supplies the authenticator issuer. No Core, Plugin or Extension dependency changes.

## Security, data and deployment

No authentication, authorization, workspace filtering, database schema or secret changes. Preserve the existing realm identifier, clients, users, roles and flows. The local Admin API reconciler must remain loopback-only, idempotent and preserve unrelated realm data. New instances copy the canonical realm/theme; existing instances need the updated image followed by `make keycloak-theme-apply`. Existing authenticator entries on personal devices require a manual rename or reenrollment.

## Milestones and validation

1. Update visible Angular text and browser metadata. Build both applications and check responsive layout.
2. Update canonical realm display/client names, theme wordmark/favicon and reconciler. Run Keycloak/theme and generated-instance tests, then verify first apply and no-op on an existing realm.
3. Verify login and a fresh TOTP QR issuer with Keycloak 26.7.5, inspect stored branding images for old wordmarks, and document rollout and rollback.

## Completion

No visible default `Mixtum` remains in either shell or login theme; a fresh OTP enrollment displays the new name. Technical identifiers stay stable. Report any unavailable real-Keycloak or physical-device check explicitly.
